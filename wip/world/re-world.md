# World stream: reverse engineering notes

Binary: `private/SLES_529.27`. Static analysis only: nothing here was run in the game.
`wip/world/check_addrs.py` rechecks the addresses it can against the ELF. gp is 0x66B170, from
the startup code at 0x100198. Names are borrowed from the PC game; behaviour is what was read.

## How opcodes were reached

`0x5F9238` holds one 16-byte entry per 100 opcodes, the handler at +8. Groups are compare
chains or jump tables, reading the opcode in `a1`. Script parameters land in `0x6FE030`;
`0x1F77D0` collects them and `0x1F7D20` stores results. The compare flag is thread +0xC5
(`0x307880`). `scm.c` has no getter for it, but it is byte 1 of "local" 34.

## Model ids differ from PC

Biggest finding. The disc's IDE files top out at 15063; PC goes to 18630. Compared by name
against the PC list at wiki.multitheftauto.com/wiki/IDE_List:

- 14695 PC ids exist on PS2, and 6164 of them have a different number.
- Whole files moved: PC 16000-16775 is PS2 11680-, 17000-17473 is 13909-, 17500-17970 is
  6390-, 18000-18101 is 14920-, 18200-18609 is 12469-. Smaller shifts of 1 to 140 run through
  4698-6525, 9519-11416, 12800-13492 and 14450-14640.
- 168 PC names are not on the disc. SA-MP's added models never were.

A server asking for 18450 (a road bridge) would otherwise get whatever PS2 numbers 18450,
which is past the end of the model table: a crash. `feat_world_models.h` is generated by
`gen_modelmap.py`, 158 segments, 1.2 KB. Everything with a server model id must go through
`wg_model_map`. Skins, vehicles, weapons and pickups below 1500 keep their ids.

## Pools and limits (CPools::Initialise, 0x265F00 onward)

| Pool | Pointer | PS2 size | PC size |
|---|---|---|---|
| peds | gp+0x828, 0x66B998 | 74 | 140 |
| vehicles | gp+0x82C, 0x66B99C | 70 | 110 |
| buildings | gp+0x830, 0x66B9A0 | 12000 | 13000 |
| objects | gp+0x834, 0x66B9A4 | 250 | 350 |
| dummies | gp+0x838, 0x66B9A8 | 2300 | 2500 |

CPool is objects +0, flags +4, size +8, top +0xC. Flag bit 7 means free (`0x1B6240`). Handles
are index<<8 | flag byte (`0x1FFB30`). Strides: object 412 (`0x1B62B4`), building and dummy 56
(`0x266B30`). `CObject::Create` is 0x1B0F70; when the pool is full it returns 0 and the opcode
handler writes through it anyway (0x30D668), so `feat_world_obj.c` keeps a reserve.

Radar blips: `ms_RadarTrace` 0x701F80, stride 40, 175 entries. Pickups: 0x8031F0, stride 32,
620 entries. Race checkpoints: 20 slots at 0x6FDC30.

## Models and streaming

- `ms_modelInfoPtrs` 0x7A8800. Handlers do not check it: 0x30D62C loads the pointer and
  0x30D638 stores through it, so a null entry is a stomp.
- Stream info 0x7C3CF0, stride 12 (PC is 20). +6 low three bits: 1 loaded, 2 requested.
- 15080 is the first non-model id (`0x2C1594`).
- `ms_memoryUsed` gp+0xD1C, `ms_memoryAvailable` gp-0x42E8 (`0x2C5710`), models queued gp+0xD18.

## Objects

- `0453` converts degrees and rebuilds the matrix (0x3313E0). `0681`/`069A`/`069B` take degrees
  too (0x49CB24). All of them deref the handle they get with no null check.
- `029B` sets the object type at +0x138 to 2, or to 6 when thread +0xC9 is not -1 (0x30D64C).
  Our thread is zeroed, so `wg_object_create` sets it to -1 around the call.
- Z of -100 or lower means "find the ground" (0x30D698).
- Entities: placement +4, matrix +0x14, flags +0x1C (bit 0 collision, bit 7 visible),
  model +0x22, area +0x2F. Current area gp+0x778. Area 13 shows in every interior (0x118368).

## RemoveBuilding

No opcode reaches buildings, and `0363` needs a nearby search that only handles one object.
Hiding is two flag bits at +0x1C, the same bits `0363` writes (0x312CC0). Buildings come back
when their IPL streams in again, so the pools are walked continuously, 800 entries a frame.

## World to screen: RE, not opcodes

`CSprite::CalcScreenCoors` is **0x11D0E0**: `a0` in, `a1` out, `a2` w, `a3` h, `t0` far check,
`t1` near check, returns 1 when visible. All-int signature, so a plain C call works under N32.
It transforms by the view matrix at 0x6FEFB0 (TheCamera +0xA00) and multiplies by the literals
640 and 448 (0x11D1A0, 0x11D190), so output is already virtual coordinates. 15 callers.

## Radar

`CRadar::DrawAreaOnRadar` is **0x26E5A0**: `a0` rect, `a1` RGBA, `a2` in menu. Corners read
(r0,r3) (r2,r3) (r2,r1) (r0,r1), and the gang overlay at 0x26E9BC fills it as min x, max y, max
x, min y. It uses the rotation and scale the radar left at gp+0x860, so it must run after the
radar. Called with 0 it checks against the radar's bounds first. `0x26E8C0` is the gang overlay,
called from the radar and from the menu map.

Blip positions are at trace +8 and could be moved in place, which would stop
`feat_dialog_hud.c` recreating a blip for each packet 208.

## Gravity

There is no variable: 0.008 is a `lui 0x3C03; ori 0x126F` pair in 24 places, and a literal in 9
`.sdata` slots. The PC game shares one literal between all of them, which is why writing
0x863984 worked there. `wg_gravity` rewrites all 33. `check_addrs.py` proves the list complete.

## Clock

Hours gp+0x6BC, minutes gp+0x6C0, written by `0x22CED0` (CClock::Update). The PC client patches
Update to return; here the tick writes the two bytes back each frame, no code patch. The HUD
clock is `sprintf` of the format at 0x5FE9E0 (0x2AB454): an empty string hides it, which is the
PC client's method too.

## Help boxes

Three setters write the buffers at 0x7C3010, 0x7C3110 and 0x7C3210: `0x2A9200`, `0x2A93C0`,
`0x2A9550`. Both `PRINT_HELP` and the stat messages go through them; the "Respect" box is one
of those stat messages, set off by the clothes `game_boot` gives CJ. `wg_kill_help` makes all
three return at once. gp+0xE88 looks like a gate but it hides the whole HUD (0x2ADA2C).

## Pickups

`CPickups::Update` (0x2D9420) calls `CPickup::Update`, and on true records the handle in a
20-entry ring at 0x8081B0 (`0x2DFE80`). `0214` just searches that ring and clears the hit, so
the tick reads the ring directly instead of one script run per pickup. Type 0 marks a slot free
(0x2D98BC).

## Checkpoints

`CREATE_CHECKPOINT` is 0x49A830, types 0 to 8 through a switch (0x49A8E8). The `00FE` locate
opcode with its sphere flag calls 0x30AE10, which places the marker with the script's address
as its id, so it has to run every frame. Enter and leave are computed by the server from sync.

## Scripts and audio

- `018C` goes to a compare chain at 0x58F160: any id is safe, an unknown one does nothing.
- `ADD_BLIP_*` read the output variable before writing it (0x318800), but only to validate it.
- `04BB` sets gp+0x778 and calls 0x2C4DB0 to reload for the area.
